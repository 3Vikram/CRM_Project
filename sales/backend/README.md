# Sales backend

## Reports analytics and AI assistant

Sales analytics uses the authenticated user's Sales records and role-based scope. Managers see their own records and direct reports identified by the employee `reportingTo` field; employees see only records they own or are assigned. This CRM has no Team entity, so team-specific reports show an explicit unavailable state. Excel export is generated by the Sales backend; PDF export uses the browser's print-to-PDF dialog.

The AI assistant sends only authorized, date-filtered Sales aggregates to a **local, self-hosted OpenAI-compatible inference service**. It does not call an external AI provider. The default endpoint is `http://127.0.0.1:11434/v1/chat/completions`, with model `llama3.1` (for example, an Ollama service listening on localhost).

To enable the assistant:

1. Install and start a local inference service on the Sales backend host, and download a compatible model.
2. Set `SALES_AI_BASE_URL` if the service uses a different localhost endpoint.
3. Set `SALES_AI_MODEL` to the installed model name.
4. If the local service requires authentication, set `SALES_AI_API_KEY` on the backend only.

### Windows setup with Ollama

Run these commands on the same Windows computer that runs the Sales backend:

```powershell
winget install --id Ollama.Ollama -e
```

After installation, open a new PowerShell window. Start Ollama from the Start menu if it is not already running. Alternatively, run `ollama serve` in a separate PowerShell window and leave it open. Then download the configured model:

```powershell
ollama pull llama3.1
ollama list
```

Verify the local Ollama API and the OpenAI-compatible endpoint used by the backend:

```powershell
Invoke-RestMethod http://127.0.0.1:11434/api/tags

$body = @{
  model = "llama3.1"
  messages = @(@{ role = "user"; content = "Reply only OK" })
  stream = $false
  response_format = @{ type = "json_object" }
} | ConvertTo-Json -Depth 6

Invoke-RestMethod -Uri "http://127.0.0.1:11434/v1/chat/completions" `
  -Method Post -ContentType "application/json" -Body $body
```

The chat request should return a completion. No `SALES_AI_BASE_URL` or `SALES_AI_MODEL` entries are required in `sales/backend/.env` for this default setup. If you add or change either value, restart the Sales backend. Keep the endpoint on localhost; the backend intentionally rejects non-local AI endpoints.

The configured AI endpoint is restricted to localhost. If the local service is unavailable or not configured, the assistant returns an explicit error and does not fabricate an answer. No AI credentials belong in frontend environment variables.

The assistant loads the authenticated user's authorized analytics from MongoDB before it calls the inference service. If a request fails, check the backend log's `phase` field:

- `sales-data`: verify the MongoDB connection and DNS/network access to the configured cluster.
- `ai-provider`: verify the local inference service is running, `SALES_AI_BASE_URL` points to its chat-completions endpoint, and `SALES_AI_MODEL` names a model installed in that service.

The API response includes a sanitized actionable error so the Reports page can show which dependency failed without exposing credentials.
